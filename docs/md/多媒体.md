# 多媒体生成

图片、语音、视频三条生成能力独立于语言模型：配置在 `media.json`，入口是侧栏「多媒体」页。对话内统一走一个 `media` 工具，脚本与快应用走 `/api/open/*`；工作台、agent 工具和接口提交的任务汇入同一条异步任务流。

## 一、为什么和语言模型分开

生成模型与对话模型是两种东西：

- 语言模型（`models.json`）驱动 agent 主循环，按 token 计费，参与上下文。
- 生成模型（`media.json`）只负责产出图片/音频/视频，按张/次/秒计费，结果落盘，不进对话上下文。

因此「多媒体」页不出现语言模型，模型页也不出现生成模型；`task` / `model_call` 的模型取值域只有语言模型。

## 二、三类能力与配置

`media.json` 按三类分开：

```json
{
  "image": [{ "name": "black-forest-labs/FLUX.1-schnell", "baseUrl": "https://api.siliconflow.cn/v1", "apiKey": "sk-...", "enabled": true }],
  "audio": [{ "name": "FunAudioLLM/CosyVoice2-0.5B", "baseUrl": "https://api.siliconflow.cn/v1", "apiKey": "sk-...", "enabled": true }],
  "video": [{ "name": "MiniMaxAI/MiniMax-H3", "baseUrl": "https://api.siliconflow.cn/v1", "apiKey": "sk-...", "enabled": true }]
}
```

| 类别 | `media.json` 键 | 能力 |
| --- | --- | --- |
| 图片 | `image` | 文生图，按张计费 |
| 语音 | `audio` | 文本转语音，按输入计费 |
| 视频 | `video` | 文生视频，最贵，通常数分钟 |

- 每类可配多条模型，至多一条启用；启用项就是该类能力的生效模型。
- 整类没有启用项（未配置或全部关闭）= 当前无此能力；工具仍存在，调用会返回「当前无…能力」，模型据此如实告知用户。
- 添加时提供预设（图片 FLUX.1-schnell / Kolors，语音 CosyVoice2，视频 MiniMax-H3），端点与密钥仍需自己确认。
- 条目字段与语言模型一致：`name` / `baseUrl` / `apiKey` / `headers`；`apiKey` 随 `media.json` 以仅属主可读权限落盘。
- 保存走 `POST /api/media`，后端重建 agent 装配；分支正在跑时返回 409，等本轮结束再改。

## 三、工作台

「多媒体」页分「工作台」与「模型与限额」两块。

工作台自己可以提交图片/语音/视频，并实时展示任务流：

- agent 的 `media` 工具与 OpenAPI 提交的任务汇入同一条任务流，不是在三个地方各看各的。
- 任务按提交时间新→旧排列，显示排队 / 进行中 / 完成 / 失败、模型、摘要与配额。
- 完成后可预览产物、在资源页打开、插入到对话；失败显示原因。
- 页面开着时每 2 秒轮询一次任务与配额，关闭页面不终止后台任务。

「模型与限额」维护三类模型条目、启用开关和每日配额（见下节）。

## 四、异步任务

生成是异步任务，提交即返回：

```
queued → running → done | failed
```

- 图片/语音通常十几秒完成，视频通常数分钟。
- 对话内 `media` 工具提交后短等待约 15 秒：完成直接返回产物路径；未完成返回任务 id，之后隔 1–2 分钟用 `action=status` 查一次，**不要连续快速轮询**（查询不会加速上游生成）。
- OpenAPI 的 `wait_seconds` 默认 10 秒、上限 60 秒，只决定本次响应等多久，任务本身继续在后台跑。
- 产物写入 `<工作目录>/tmp/`；`job.files[].path` 是产物本机绝对路径，图片/音频详情另带内嵌 base64，视频只给原始 URL。
- 任务档案持久在 `mediajobs.json`，封顶 200 条；core 重启时未完成任务标记失败并退还当日配额（上游任务 id 已随进程丢失，v1 不续查）。

### 每日配额

配额是审批之外的第二道闸，按类别计数：

| 类别 | 默认限额 | 计量 |
| --- | --- | --- |
| 图片 | 20 | 张 |
| 语音 | 20 | 次 |
| 视频 | 3 | 次 |

- 在「模型与限额」调整，0 表示使用默认值。
- 配额在提交时占用，彻底失败（无产物）退还；工具结果与 OpenAPI 响应都附带用量视图。
- 超限时 OpenAPI 返回 429，工具返回「今日配额已用完」——不要重试，等第二天或调整限额。

## 五、对话内：一个 media 工具

图片、语音、视频、任务查询共用一个工具，按 `action` 分派：

| action | 必填 | 可选 | 说明 |
| --- | --- | --- | --- |
| `image` | `prompt` | `negative_prompt`、`image_size`（如 `1024x1024`）、`batch_size`（1–4）、`seed` | 文生图 |
| `audio` | `input`（≤5000 字符） | `voice`（alex / anna 等短名）、`format`（mp3/wav/opus/pcm）、`speed`（0.25–4） | 语音合成 |
| `video` | `prompt`（镜头脚本，≤200 词） | `duration`（5–15 秒）、`resolution`（480p/768p）、`ratio`、`first_frame`、`last_frame` | 文生视频 |
| `status` | — | `id`（省略=最近任务） | 查询任务/产物 |

调用纪律：

- 先看 system 的 `<media>` 段确认能力；未配置/已关闭的能力直接如实回复「当前无…能力」，不要试探、不要重试、不要改用其他方式硬凑。
- 参数、成本与轮询细节先 `load_skill media`，不要凭记忆猜。
- `media:image` / `media:audio` / `media:video` 默认每次调用都需要审批，`media:status` 免审；非用户明确要求，不要放大 `batch_size`、拉长视频时长或反复微调重试。

## 六、OpenAPI 与 SDK

脚本、快应用页面/后端、外部程序走 OpenAPI 面（鉴权见[认证与 OpenAPI](认证与openapi.md)）：

| 端点 | 载荷 | 返回 |
| --- | --- | --- |
| `POST /api/open/image/call` | `{prompt, model?, negative_prompt?, image_size?, batch_size?, seed?, wait_seconds?}` | `{ok, job}` |
| `POST /api/open/audio/call` | `{input, model?, voice?, response_format?, speed?, wait_seconds?}` | `{ok, job}` |
| `POST /api/open/video/call` | `{prompt, model?, duration?, resolution?, ratio?, first_frame?, last_frame?, wait_seconds?}` | `{ok, job}` |
| `GET /api/open/media/jobs?limit=` | — | `{jobs}`（新→旧，清单不含内嵌 b64） |
| `GET /api/open/media/jobs/:id` | — | `{job}`（done 带 files / failed 带 err） |

SDK 封装同名能力：

```js
ez.config({ token: 'openapi 令牌' })
const { job } = await ez.gen.image('一张产品海报…', { image_size: '1024x1024' })
const done = await ez.gen.job(job.id)   // done.files[].path 是本机绝对路径
```

- `ez.gen.image / speech / video / job / jobs` 与 `media` 工具共用任务引擎与每日配额。
- 配额超限返回 429；参数或配置问题返回 400（含「当前无 X 能力」的说明）。
- 快应用既能直接调用生成接口，也能让后端转调；两条路径的产物都落在工作目录 `tmp/`。

## 七、资源与上下文

- system 的 `<media>` 段固定列三类能力与当前生效模型；未启用的显式标注「当前无此能力」。
- 轮内启用、关闭、切换模型由下一轮开头的 `<resource_change>` 告知模型。
- 多媒体参数与成本唯一归属 `media` 内建技能；系统提示只保留能力清单，不重复机制文本。
- 生成模型不进 `<models>`（那是语言模型清单），也不参与 `task` / `model_call` 的模型选择。

## 八、配置与排错

1. 打开侧栏「多媒体 · 模型与限额」，为需要的类别添加模型并启用。
2. 到工作台提交一次最小请求，确认能力、产物路径与配额。
3. 对话里让 agent 生成时，先说清用途；未配置的能力会直接回复「当前无此能力」。

常见结果：

| 现象 | 原因 / 处理 |
| --- | --- |
| 工具回复「当前无…能力」 | 该类没有启用模型；到「模型与限额」启用 |
| OpenAPI 429 / 工具提示配额用完 | 当日配额超限；等第二天或在页面调高限额 |
| 400 参数错误 | 缺少 `prompt` / `input`，或参数越界（时长、张数、字符数） |
| 任务失败 | 查看任务详情里的 `err`；失败不计配额，可修正后重试 |
| core 重启后任务变成 failed | 进程重启中断了未完成任务；配额已退还，重新提交 |
