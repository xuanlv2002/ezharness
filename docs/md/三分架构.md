# 三分架构

> 三个 exe、一个常驻 core：ezharness.exe 是唯一命令入口，ezharness-desktop.exe 是 GUI 壳，ezharness-core.exe 承载全部能力；两枚令牌、默认密码隐式登录，本机优先。

## 一、形态与职责

| 产物 | 形态 | 职责 |
| --- | --- | --- |
| ezharness-core.exe | console 服务进程 | 全部后端能力：HTTP + 内嵌 web 端、agent 引擎、终端、MCP、回调、多媒体、无头浏览器后端 |
| ezharness.exe | console 入口 | 唯一命令入口：子命令 + 无参信息卡；纯 core 的客户端，不 import core 内部包（独立 Go module） |
| ezharness-desktop.exe | GUI 壳 | 窗口/托盘/悬浮球/真实浏览器抽屉/预览壳；附着 core，不拥有 core |

一个安装包装三个 exe，写 HKCU PATH，快捷方式指向 desktop。

## 二、进程地基：常驻单实例 + ensureCore

core 常驻单实例，三个入口退出都不杀它；停止只经 `ezharness stop` 或进程信号。

- **server.json**（应用根，与 ezharness.json 同目录）：`{port, pid, version, dataDir}`，**不含任何令牌**。core 启动写、退出删；bind 成功后才写，所以残留文件一定指向已死的实例，新实例直接覆盖。
- **ensureCore()**（三入口共用）：读 server.json → `GET /api/app/health`（300ms 短探活）→ 存活即附着；没跑则拉起（detached core，轮询就绪上限 10s）。版本不做强制校验：core 常驻，升级后用 `ezharness stop` 停掉旧实例，新端下次启动自然拉起新版。
- **bind 仲裁**：端口 bind 成功者即主 core，抢不上即附着既有实例——重复启动不报错、不双活。
- health 免鉴权，回 `{ok, boot, version}`。

## 三、认证

两枚令牌、两个信任域，全部显式请求头：

| | 会话令牌 | OpenAPI 令牌 |
| --- | --- | --- |
| 请求头 | `EzHarnessToken` | `EzHarnessOpenToken` |
| 谁用 | desktop / cli / 浏览器页面（人驾） | agent 产物：脚本、快应用、外部程序 |
| 权限 | 全量 `/api/*`（用户界面） | 仅 `/api/open/*`（外部程序；不认会话凭证） |
| 来源 | 默认密码 login 签发 | `create_openapi_token` 工具 / 安全页生成（无默认，多枚可命名、可吊销） |
| 生命周期 | 持久（core 重启不换），多端并存 | 持久，随时吊销 |

**默认密码**：core 启动时检查数据目录 `auth.json`（0600）：没有密码哈希、哈希损坏或不是默认密码 `ezharness` 时，重建默认密码哈希并清空旧会话。web / desktop / cli 不显示登录页或密码提示，启动时用默认密码静默换会话令牌；令牌各自持久保存，失效自动重登。改密码与显式登录留给远程形态。

**OpenAPI 令牌**：没有默认令牌。agent 需要调 `/api/open/*` 时用 `create_openapi_token` 工具生成，用户也可在安全页生成；令牌显式放进 `EzHarnessOpenToken` 请求头，不注入环境、不认会话凭证。MCP 的 `401 + needs_auth` 是 OAuth 授权，不是令牌失效。

**端点**：`POST /api/auth/login`（默认密码换令牌）、`POST /api/auth/logout`（会话面，撤销当前令牌）。免鉴权面全量清单：health、`/api/auth/login`、`/api/open/sdk.js`、`/apps/*` 静态资产（快应用页面本身无秘密，秘密在页面里的 OpenAPI 令牌）。

**传输**：

- 页面 fetch 层的会话接口一律带 `EzHarnessToken` 头；令牌浏览器存 localStorage（新标签页、重启后仍可带头与建 WS）。
- `<img>`/`<video>`/PDF/页面导航这类浏览器自动发起的请求加不了自定义头——登录响应同时下发 HttpOnly cookie（SameSite=Strict）作**资产传输适配**，不是第二套认证；cookie 只在只读 HTTP 请求（GET/HEAD，含 SSE）上生效，状态变更接口必须带显式请求头（`cookie` 按 host 生效不看端口，不限制方法会被同机其他端口页面借浏览器 CSRF）。
- WebSocket 握手用子协议带令牌：`new WebSocket(url, ["agent-auth", token])`，后端从 `Sec-WebSocket-Protocol` 解析校验并回显 `agent-auth`。握手虽然也是 GET，但不接受 cookie——连上就能发命令，必须显式带令牌；桌面桥这类非浏览器客户端走 `EzHarnessToken` 头。
- desktop / cli 把令牌存各自的凭证文件（壳的用户目录，不在 core 数据目录——为远程形态预留）。desktop 固定跟随本机 server.json；cli 默认连本机 core，`--server` 可显式指定地址。core 仍只绑 127.0.0.1，当前实际用途是本机另一实例/端口。
- 安全页的登录会话按端列出：客户端类型、来源 IP（socket 地址）、登录时间、会话 id；旧会话没有来源字段时显示"来源未知"。

**审计**：仅 `/api/open/*`。每笔调用记 jsonl（时间、端点、令牌名、状态码），按大小轮转，安全页可查。会话面不审计。

**监听**：本阶段一律 `127.0.0.1`，设置面不提供修改。默认密码与隐式登录只用于本机形态；改监听（远程门户）作为预留入口后续再开——开了也只放行 `/api/open/*` + 登录。

## 四、浏览器双后端

| 后端 | 条件 | 能力 |
| --- | --- | --- |
| 桥后端 | desktop 壳在场（WS 桥已连接） | 真实 Chromium、抽屉实时可见、用户可接管 |
| 无头后端 | 其余一切（core 单跑 / TUI / web） | chromedp 驱动本机 Chrome/Edge（headless），无抽屉 |

桥连接时优先桥；无头后端探测系统已装浏览器（Windows 出厂自带 Edge 即可用）。探测失败的工具报错是 agent 可读的：写明安装指引（如 `winget install Google.Chrome`），agent 自行安装或请用户安装后重试——不捆绑浏览器二进制。

## 五、远程形态（预留，当前不做）

本阶段一律本机。将来开远程门户时，能用的只是"对话/模型直调/多媒体/MCP"这类纯后端能力；快应用与终端里的东西是本地回环语义，远端页面访问不到，core 不为它们做代理——远程形态如实标注为部分能力可用，而不是假装全部可用。

## 六、目录

```
core/            Go module ezharness/core   → ezharness-core.exe
  frontend/      Svelte 源码（core 的内嵌 web 端）
  web/dist       前端构建产物（不入库，embed 进二进制）
cli/             Go module ezharness/cli    → ezharness.exe（纯 core 客户端）
desktop/         Electron                   → ezharness-desktop.exe
script/ docs/ assets/ release/
```
