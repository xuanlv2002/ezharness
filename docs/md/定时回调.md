# 定时回调

> 对话是现在发生的事，定时回调是「到点以后」发生的事。

## 一、它是什么

定时回调是 ezharness 的全局回调中心，与对话、快应用平级。它回答一个问题：**到某个时间，让哪条会话继续做事、让哪个快应用动起来，或者在工作目录跑哪条命令？**

任务存在数据目录的 `callbacks.json`，由 core 的调度器执行。任务和 skill / MCP / 快应用一样是可发现资源：进 system 清单、轮内变化走 `<resource_change>`、有独立的页面和 agent 工具。

三类任务：

| 类型 | 到点什么 | 目标 |
| --- | --- | --- |
| 会话回调 | 向一条会话发送消息 | 创建时选定的会话；或每次新建会话 |
| 快应用回调 | 触发一个快应用 | 自动启动后端，调用 `app.quick` 声明的端点 |
| 脚本回调 | 执行一条 shell 命令 | 本机工作目录；输出尾部与退出码进记录 |

## 二、为什么需要它

没有定时回调时，「明天早上提醒我」「每小时同步一次」只能靠外部 cron + 脚本，或者人自己记着。对话里的 `sleep` 只能在一轮内阻塞等待，关掉窗口就没了。

定时回调把这些需求收进工作台：

- 计划与会话绑定，消息直接进入对话时间线，不是游离在外的通知；
- 快应用的接口在 `app.quick` 里声明一次，计划可以反复改；
- 工作目录里已有的脚本可以直接挂计划，不必先包成快应用；
- 每次触发留下记录，事后能看到什么时候、往哪、发了什么、结果如何；
- 任务能在页面、状态卡、快应用卡片和系统提示里被看见，不需要读配置文件。

## 三、计划表达式

三种计划，均按本机时区解释：

| 类型 | 写法 | 语义 |
| --- | --- | --- |
| 单次 | `once` + `at: "2026-11-01 09:00"` | 到点执行一次，执行后转「已完成」终态 |
| 固定间隔 | `interval` + `every: "30m"` | 执行完从完成时刻重新计时，最小 10 秒 |
| 日历 | `cron` + `"0 9 * * *"` | 5 段：分 时 日 月 周，周日=0；日与周都受限时任一命中即可 |

间隔与 cron 不补跑应用停机期间错过的触发：启动时从当前时间重算下一次。一次性任务如果停机期间错过，标记 `missed` 并转「已完成」，避免几天后突然补发一条过期消息。

## 四、会话目标与运行语义

会话回调有两种目标：**指定会话**，或**每次新建会话**。页面创建时可以从现有会话列表里选，默认当前会话；`callback` 工具用 `session.sessionId` 指定，省略时绑定调用方当前会话。

指定会话模式存的是**创建任务时选定的叶 session ID**，不是分支根。任务只认这个会话：它后来被归档，或者被 compact 换代成新叶，任务就失败并记录原因，**不会继承到新会话**；需要继续就重新创建任务。任务的消息与目标都在 `callbacks.json`，不会因为上下文压缩被悄悄改绑。

到点执行时：

- **目标正在跑一轮**：复用 chat 的打断式发送——先取消当前轮，等它收尾（最多 8 秒）后立刻发送新消息。定时消息不排队，也不让旧轮继续占用目标。
- **目标正在归档**：直接失败并记录，不等待归档结束。
- **目标已归档 / 已换代**：直接失败并记录，消息不会写进归档库或新会话。
- **新建会话模式**：每次触发创建一条新会话再发送，适合「每次从干净上下文开始」的任务。

投递到会话的用户消息带一层元数据标记：

```text
<scheduled_callback>{"taskId":"cb-…","title":"每日早报","at":"2026-11-01 09:00:00"}</scheduled_callback>
正文
```

标签只承载任务名与触发时间，正文才是本轮指令。前端把它渲染成带「定时回调 · 任务名 · 时间」卡头的用户消息，并可点「查看任务」回到回调详情；模型收到时按标签后的正文执行。

## 五、快应用触发

快应用在 `app.quick` 里声明可被定时调用的端点（`callbacks` 数组）：名称、方法、绝对 URL、可选 headers/body。声明只描述接口，计划归任务。

任务只引用 `app.name + callbacks[].name`，没有「启动后端 / 调用端点」两种动作可选：

- 触发时若应用声明了 `backend`，先确保后端在共享终端里运行；
- 然后按声明的方法、URL、headers、body 调用端点，连接失败在约 15 秒内重试；
- 非 2xx 或连接失败记为失败，响应摘要进运行记录；
- 不覆盖声明里的 body；同一接口只需要一处定义，可以挂多条计划。

端点后是什么由应用自己决定：可以是一个 HTTP 接口，也可以由脚本或本地进程提供。执行器只负责按时启动应用并发出这次调用，不打开快应用窗口。

## 六、脚本执行

脚本回调只存一条 shell 命令（`script.command`），不需要先包成快应用。触发时：

- 在 agent 工作目录（terminal 的默认目录）执行：Unix 用 `$SHELL -c`，Windows 用 `cmd /C`；
- 合并 stdout/stderr，保留末尾 64 KB；运行记录显示输出尾部与退出码；
- 退出码 0 记为成功，非 0 记为失败并保留输出；
- 单次上限 10 分钟，超时或应用退出会结束整个进程树；
- 命令可以写 `./sync.sh`，也可以写 `python tools/sync.py`；脚本文件本身放工作目录。

脚本任务不接管应用窗口；结果看任务详情与「回调记录」。

## 七、记录与通知

每次触发（成功、失败、跳过）都会给任务追加一条运行记录：

| 字段 | 内容 |
| --- | --- |
| 触发时间 | 实际开始执行的时间（本机时区） |
| 目标 | 会话 ID，或快应用名 + 端点名，或脚本 |
| 触发内容 | 会话消息正文，或 `方法 URL · body`，或脚本命令 |
| 结果 | HTTP 状态、发送结果、脚本退出码与输出尾部，或错误原因 |
| 方式 | 按计划触发，或页面/工具「立即运行」 |

每个任务保留最近 30 条；「回调」页按页展示任务，点任务标题打开详情，可以看到创建时间、完整配置与该任务的全部触发记录；页面底部再按时间汇总所有可见任务的记录，会话类记录可直接点进触发的会话。删除任务会一并删除它的记录。

每次触发都写一条待确认通知，标题是任务名，详情带目标与结果：会话投递成功时点通知直接打开目标会话；快应用、脚本或失败时点通知打开「回调」页并展开该任务。通知不会自动变成已完成——用户点「知道了」后才清除，避免触发信息一出现就被当成已读略过。会话回调本身会启动一轮对话，轮结束的完成通知仍由对话通知体系负责。

## 八、发现与可见性

| 位置 | 看到什么 |
| --- | --- |
| 左侧「回调」页 | 分页任务表：启用中的置顶、组内按创建时间新→旧；计划、目标、下次时间、上次结果、创建时间；点标题看详情与单任务记录；可启停、立即运行、编辑、删除（已完成的不可编辑，仍可查看、手动触发、删除） |
| 对话页「运行状态」弹层 | 当前会话绑定的未完成任务（标题、计划、下次运行） |
| 快应用页卡片 | 该应用关联的定时任务与已声明的端点 |
| system `<callbacks>` 段 | 循环任务与未完成的一次性任务；已完成的一次性任务不进清单，绑定当前会话的标注「本会话」 |
| `<resource_change>` | 轮内新增/更新/启用/停用/移除的回调（一次性任务完成按「移除」报告一次） |
| 通知栏 | 每次触发一条待确认通知：成功投递会话时点开直达会话，其余点开定位任务；点「知道了」清除 |
| `callback` 工具 | agent 的唯一配置入口：list/create/update/delete/enable/disable/run（list 不含已完成的一次性任务） |

清单常驻上下文，配置不靠读文件；`callbacks.json` 与 settings、topics 一样属于禁区。

一次性任务的生命周期由此收敛：启用中＝待触发，进 system 清单与工具 list；按计划触发（无论成败）或停机错过后转「已完成」——不再进 agent 可见的任何清单、不可编辑启停，但手动「立即运行」与删除始终可用，触发记录也原样保留。停用状态的一次性任务时间一旦过期，下次启动直接转「已完成」。

## 九、运行边界

- **core 运行期间才执行**。ezharness 关闭时没有后台守护进程；重启后按上述错过语义校正。
- **不会绕过审批**。定时任务发起的对话轮仍然走当前审批档位与安全策略；无人值守时可能停在审批卡上。
- **脚本任务直接执行命令**。创建动作经过页面或 `callback` 工具审批；到点执行时不再二次确认，命令的副作用由创建者负责。
- **不自动弹窗**。快应用触发只保证后端启动并调用端点；打开快应用窗口仍由人点卡片或 agent 交付入口。
- **一次性任务只按计划尝试一次**。执行失败也转「已完成」并保留错误；手动「立即运行」不消耗计划、随时可重跑，要再按计划跑就新建任务。
- **状态与配置同一文件**。运行态（下次/上次/结果/记录）由调度器维护，页面的编辑操作只改配置字段。
