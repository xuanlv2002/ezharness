# 模型配置

模型配置分成两套，互不进入对方的取值域：

- **语言模型**（`models.json`）：驱动 agent 主循环，也是 `task` / `model_call` 可按名选用的模型池。
- **生成模型**（`media.json`）：图片、语音、视频三类多媒体能力，统一走 `media` 工具与 `/api/open/*`。

两套配置各自保存、各自重建装配。生成模型不出现在模型页，语言模型也不会被生成任务使用。

## 一、语言模型只有一个槽

| 槽位 | 作用 | 约束 |
| --- | --- | --- |
| `main` | 驱动 agent 主循环；多模态时直接接收图片 | 不可为空，必须有启用项 |

模型页的职责因此收敛为两件事：维护模型条目，并点亮**新会话的默认主模型**。已有会话在输入框各自切换，互不影响。`models.json` 只读取 `main`；如果文件里残留旧的 `image` / `audio` / `video` 字段，直接忽略，不参与任何配置。

## 二、一条模型配置

```json
{
  "name": "deepseek-flash",
  "protocol": "openai",
  "baseUrl": "https://api.deepseek.com",
  "apiKey": "sk-...",
  "contextWindow": 128000,
  "vision": false,
  "headers": {},
  "enabled": true,
  "disabled": false
}
```

| 字段 | 含义 |
| --- | --- |
| `name` | 模型名，同时作为调用标识 |
| `protocol` | `openai`（默认）/ `responses` / `anthropic`，空串按 openai 处理 |
| `baseUrl` | 服务端点；三种协议使用同一组 apiKey / baseUrl / headers |
| `apiKey` | 为空仍可启动，但发消息会被拒绝 |
| `headers` | 附加请求头，用于网关、组织 ID 等 |
| `contextWindow` | 上下文窗口 tokens；`0` 表示未知，装配时按 128000 兜底 |
| `vision` | 主模型是否能把图片直接放进上下文 |
| `enabled` | 主模型当前选用；同一时刻至多一条启用 |
| `disabled` | 关闭该模型；关闭后不进入可选清单，`model_call` / task 也无法调用 |

`enabled` 与 `disabled` 不是一件事：前者是「现在用谁」，后者是「这条还能不能用」。

## 三、厂商预设

添加模型时提供三条预设，点击即回填五项：名称、端点、上下文窗口、视觉能力、协议。

- 智谱 GLM
- DeepSeek 官方
- 硅基流动（DeepSeek）

预设只负责减少填错，不限制你手动改任何字段。API Key 始终需要自己填。

## 四、生效时机

模型配置的变更不走「立即覆盖」：

1. 保存配置 → `POST /api/models`，后端重建 agent 装配（Reassemble）。
2. 若该分支正在运行，保存返回 409，等当前轮结束再改。
3. 成功后的提示是「下一轮生效」；运行中的分支在轮末切换到新装配。
4. 在输入框切换本会话主模型走 `POST /api/sessions/<分支根>/prefs`，只重建该会话装配，同样从下一次输入开始生效。

这样做避免在一轮对话中途换引擎，导致历史、上下文与工具状态错位。生成模型的保存同样会重建装配，见[多媒体](多媒体.md)。

### 主模型、思考与审批都是会话级

- `models.json` 里点亮的 `enabled` 只是**新会话默认**；会话首次装配时会把当时生效的模型钉进会话，之后改默认不再牵动它。切换分支时输入框显示该分支自己的模型。
- 思考强度与审批档位同样按会话保存：输入框下拉只改当前会话，即改即生效（审批由工具调用前的闭包实时读取，不需要重建 agent）。
- 新建分支从当前会话继承三项偏好；分叉从源会话继承；compact 换代随线保留。没有来源时用默认值：思考「默认」、审批「跟随安全配置」、模型为全局点亮的那条。
- 会话正在跑或归档时切换模型返回 409，等本轮结束再切；思考/审批不受此限。
- 偏好落盘在会话目录（`prefs.json`），并随快照保存一份；重启、切回分支都不会丢。

## 五、视觉能力

`vision` 不是装饰字段，它改变请求形态：

- 开启时，图片消息原样进入上下文。
- 关闭时，`visionguard` 在请求副本中剥除所有图片，并把图片标记改写为带 `omitted` 说明的文本；落盘历史不受影响，换回多模态模型后自动恢复。
- 无视觉模型下，`read_file` 读取图片会被拒绝，浏览器截图改走文件路径，`model_call` 带图直接报错。

## 六、用量统计

每轮结束把用量写入 `stats.json`：

- 按本地小时分桶（`YYYY-MM-DDTHH`），字段 `turns` / `in` / `out` / `cache`，并按模型拆分。
- 小时桶保留 30 天；累计总量永久保留。
- `models.json` 的每条模型另有累计 `inTokens` / `outTokens` / `cacheTokens`。

前端两个入口：

- 模型页头的「用量统计」：24 小时 / 7 天 / 30 天，输入、输出、缓存命中、轮数与按模型折线。
- 对话页状态卡的缓存命中率与上下文水位。

多媒体生成不消耗这里的 token 统计：它按张/次计入多媒体页的每日配额（见下节）。

## 七、多媒体生成模型

图片、语音、视频是三类独立能力，配置在 `media.json`，入口是侧栏「多媒体」页——与语言模型彻底分开。模型条目、启用开关、每日配额、异步任务、`media` 工具与 OpenAPI 端点统一见[多媒体](多媒体.md)。

## 八、配置的最小路径

1. 语言模型：打开「模型」页，选择预设或手动填写，填入 API Key，保存后回对话页发第一条消息。
2. 生成模型：打开「多媒体 · 模型与限额」，为需要的类别添加模型并启用，再到工作台提交一次生成验证配额与产物路径。

如果 apiKey 为空，启动不会报错，但真正调用时会明确提示缺少密钥——错误发生在需要模型的时候，而不是在启动时。
