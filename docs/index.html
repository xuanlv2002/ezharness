核心概念

Core Concepts

CONCEPTS

ezharness 的设计语言：三支柱与两个关键模型。

The design language of ezharness: three pillars and two key models.

上下文工程Context engineering
system 两段式组装、trim 双触发（水位自动 + 模型主动）、agent_status 轮首快照、guard 窗口余量兜底。
Two-part system prompt, dual-trigger trim (watermark + model-initiated), per-turn agent_status snapshots, guard fallback by window headroom.
md/context.md →
trim 与 compacttrim vs compact
trim 是模型侧整理（就地折叠不换库）；compact 是用户侧沉淀（记忆合并 + 换代封存）——一对互补机制。
trim is the model-side cleanup (fold in place, same store); compact is the user-side distillation (merge memory, seal the generation).
md/compaction.md →
人机协同交互Human-agent interaction
对话不是唯一通道：决策、观察、操作各有专门产品面；通知全局可达，数据不绑视图。
Chat is not the only channel: deciding, watching and operating each get a dedicated surface; notifications are globally reachable.
interaction.md →
树状会话模型The session treekey model
节点是 session（一次换代内的完整对话库），线是用户视角的「会话」。树对用户只露两个操作：fork 分叉（copy 语义）与 compact 换代（沉淀式归档）；上翻沿 compress 链懒加载旧世代全文。状态即消息：全部状态是可落盘的消息库与 system，重启即恢复，折叠不丢档。
Nodes are sessions (a full message store within one generation); lines are what the user calls a "conversation". The tree exposes exactly two operations: fork (copy semantics) and compact (distilling archive); older generations lazy-load along the compress chain. State is messages: everything persists as a message store plus system — restart restores, folding never loses data.
