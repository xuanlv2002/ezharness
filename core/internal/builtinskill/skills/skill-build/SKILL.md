# 技能创建

把一类**反复出现、方法可固化**的工作写成技能。导入已有技能 → skill-install 技能。

## 判定

| 情形 | 走向 |
| --- | --- |
| 这类事做过 ≥2 次、步骤能写死、下次还想照着做 | 值得固化为技能 |
| 一次性的活、或产物是可运行的东西 | 不是技能：一次性别写；可运行的产物做成快应用（quick-app 技能） |
| 用户要装现成的技能 | skill-install |

## 做法

技能 = `<数据目录>/memory/skills/<目录>/SKILL.md`（+ 可选 `scripts/` 资源）。SKILL.md 三要素：

| 要素 | 规则 |
| --- | --- |
| frontmatter | 扁平 `name`（缺省回落目录名）+ `description`——**描述写清"什么时候用"**，agent 靠它从清单匹配 |
| 正文 | 给模型看的操作指令：目标、判定、步骤、边界；**不写实现原理** |
| 脚本 | 放 `scripts/`，正文相对路径引用；重复劳动写成脚本比写成长文更可靠 |

写完 `write_file` 落位，**下个新会话**进 `<skills>` 清单。

## 模板

```markdown
---
name: <短名>
description: <一句话：做什么的时候用本技能>
---
# <标题>

## 判定
| 情形 | 走向 |   ← 什么时候用 / 内部选哪条路 / 何时该用别的技能

## 做法
<步骤、字段、协议——能表格化就表格化>

## 模板
<可复制骨架>

## 验证
<做完怎么确认成了>

## 排错
| 症状 | 处置 |
```

内建技能（open-api / quick-app / mcp-config / mcp-build 等）都是这个骨架，写前可 `load_skill` 参考任一内建技能的排布。

## 验证

- 新会话里 `<skills>` 清单出现该技能且描述正确
- 按技能走一遍真实任务，步骤无歧义、无缺信息（缺了就补——技能是给没有上下文的下一次会话看的）

## 排错

| 症状 | 处置 |
| --- | --- |
| 清单里不出现 | 查目录层级与 frontmatter 可解析；当前会话本来就不回填 |
| agent 不主动用 | description 没写清"什么时候用"，重写描述而不是加正文 |
| 照做会翻车 | 缺协议契约/字段语义（agent 读不到源码），补事实进做法段 |
