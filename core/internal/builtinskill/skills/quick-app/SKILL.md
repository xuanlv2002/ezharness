# 快应用构建

快应用 = `<数据目录>/apps/<名>/` 目录（数据目录绝对路径见 system 提示 `<workspace>` 段，apps 行给出的是同一个位置）。目录里有 `app.quick` 声明才算一个应用。

快应用是一套与宿主无关的打包标准：协议只约定文件组织（声明、入口、启动命令、图标、文档），不约束语言与技术栈；页面里要用大模型或 MCP 能力时，调用方法见 open-api 技能。用户点击启动 = **打开应用窗口**；声明了 `backend` 就在 ezharness 内置终端里把后端跑起来。

## app.quick 协议

```json
{
  "title": "证书探测",
  "entry": "index.html",
  "backend": "python probe.py",
  "icon": "icon.svg"
}
```

- `title`：卡片标题；缺省取 entry 文件的 `<title>`，再缺省用目录名
- `entry`：前端入口（相对应用目录），缺省 `index.html`
- `backend`：启动命令，cwd 是应用目录；**省略 = 纯前端**，只开窗不起终端
- `icon`：卡片头像（相对应用目录的图片文件名，应用目录内、不可上溯）
- 未识别的字段一律忽略——协议向前兼容，加字段不会破旧版

## 先规划，再执行

多步应用（判断形态、选数据通道、页面结构、头像、落盘与验证）**先调用 plan 工具再动手**：

- `action=new` 提交方案：`plan` 按 目标/方案/步骤 写清「纯前端还是后端、数据从哪来、页面怎么组织」；`progress` 拆成 3–6 个可跟踪步骤。新方案会请用户审批，**批准后再写文件**，避免方向错了返工。
- 批准后按步骤执行，每完成一步 `action=update` 同步进度（progress 整表替换）。
- 用户改需求、原方案不再适用时重新 `new`，不要口头改方案；任务完成后保留全部 completed 即可。
- 一次 `save_app` 就能写完的纯静态小页面不用 plan。

## 应用文档与版本

- `save_app` 的 `description` / `version` / `document` 写入 `app.quick`；`description` 一句话，`version` 用语义化版本，`document` 缺省 `APP.md`。
- 可复用或要开放给 agent 的应用写应用文档（默认 `APP.md`）：frontmatter（name/description/version）+「能力 / Agent 调用 / 人类使用 / 限制」。
  **只有包含「Agent 调用」一节的应用才对 agent 开放**；这一节写清入口、输入、输出、副作用、失败语义、就绪条件——前端可以是一段 JS（如 `window.<app>.<method>()`），后端可以是 HTTP/CLI，规范不限定形态。
- 每次版本变化在应用目录追加 `CHANGELOG.md`（版本、日期、变更摘要）。
- APP.md 骨架（可直接复制）：

```markdown
---
name: certprobe
description: 探测域名 HTTPS 证书链与到期时间
version: 1.0.0
---
# 能力
一句话：输入什么，产出什么。

# Agent 调用
入口：（页面内 JS window.certprobe.probe({...}) / POST http://127.0.0.1:18731/api/probe / CLI）
输入：参数名、类型、必填
输出：返回结构与示例
副作用：只读 / 写哪里 / 起进程
失败语义：reject / 非 2xx {"error":...} / 退出码
就绪条件：后端需先启动；首次调用按 3 次×300ms 重试
```

  六要素（入口/输入/输出/副作用/失败语义/就绪条件）一个不能少；不需要 agent 调用的应用**不要写这一节**。
- 使用已有应用：清单在 system 的 `<apps>` 段（轮内新增/移除见 `<resource_change>`），用 `load_app` 读调用文档；不要凭 `app.quick` 猜调用方式，也不要给没有「Agent 调用」一节的应用臆造接口。

## 怎么建

**先判断形态，别一上来就写后端：**

1. **够用 HTTP 就不起后端**：页面里直调大模型、调 MCP 工具都是一次 HTTP 请求（用法与鉴权见 open-api 技能）；`file://` 直接打开页面就能测试。
2. **纯前端**：`save_app`（name/title/html）一次写全 `app.quick` + `index.html`。
3. **需要后端**：要长期可靠调核心能力、或需要本机命令能力（TLS 证书探测、本地文件处理、调非 MCP 的本地程序）而 MCP 覆盖不了时，`save_app` 带 `backend` 建骨架，再用 `write_file` 把后端脚本等文件写进同一目录（save_app 只写声明与前端，它引用的脚本要先写好）。后端怎么取令牌见 open-api 技能。

## save_app 的覆盖语义（必读，最容易翻车）

`save_app` 是**整页重写**，不是增量更新：

- 每次调用都会用 `html` 参数**整体覆盖** `index.html`——先 `write_file` 写了完整页面、再 `save_app` 传占位 html，完整页面就没了
- 每次调用都会**全量重建** `app.quick`——`description`/`version`/`document`/`backend`/`icon` 省略哪个，哪个就从清单里消失；**document 首次就传**，事后手改 app.quick 再 save_app 一遍又会丢

正确顺序：**先** `save_app`（html 传完整真实内容，或最小骨架）→ **再** `write_file` 补后端脚本、icon 等其余文件 → 后续增量更新用 `write_file`/`edit_file` 直接改文件，**只有整页重建才再调 save_app**（此时把清单字段全部带上）。大页面 html 参数可用 `<@toolArg>` 引用草稿文件传入。

## 头像（icon）

**建应用时顺手给一张**——快应用卡片和桌面小助手钉选都显示它。

- 首选 **SVG**（纯代码可写）：`write_file` 写 `apps/<名>/icon.svg`，`save_app` 带 `"icon": "icon.svg"`；PNG 同理（需要二进制写出时才用）。
- 绘制要求：**128×128 视图框、透明底**；一个主题色大色块背景 + 简单几何图形或 1-2 个字母/字符表意（如证书探测 → 盾形 + "TLS"），风格干净扁平；**不要**复杂插画、照片、密集文字，缩小到 16px 仍可辨识。
- 色彩用应用自己的主题色（与页面主色一致最好）；没有想法就用中性色 + 首字母。
- 没给 icon 时卡片回落默认代码图标，不报错。

## 后端约定

- 命令在**应用目录**里执行（cwd = 应用目录），相对路径直接可用。
- **前台**运行：不要 `start /b`、不要 `&`——日志留在那个终端里，用户和你都看得到；停服务 = 在那个终端 Ctrl+C 或关掉它。后台化会让输出与退出都失控。
- 端口自己定一个高位端口，页面里用同一个值。**启动时先检测端口占用**：被占就打印「端口 XXXX 已被占用——服务可能已在运行（去卡片打开即可），或先停掉旧进程」然后干净退出，不要抛栈崩溃。
- **同一后端只能跑一份**：调试时在共享终端手动跑过后端，用户再点卡片启动会因端口占用崩溃——交付前提醒用户二选一（终端里 Ctrl+C 释放，或就留在终端跑、不再点卡片）。
- 只依赖用户机器上已有的运行时（python/node 等），不要在脚本里装依赖。
- 后端在另一个端口 = **跨源**：页面直接 fetch 后端时，后端必须返回 CORS 头（`Access-Control-Allow-Origin: *`），否则浏览器拦掉。

### 就绪检查（统一范式）

点启动立刻开窗、后端可能还没监听。统一做法：

- **后端暴露 `GET /health`**（顺便探一下 core：`GET /api/open/mcp` 带令牌，返回里带上 core 连通状态）
- **页面轮询 `/health`** 而不是拿业务请求试错：至多 30 次 × 500ms（冷启动 15 秒内基本覆盖），成功后再发首个业务请求

```js
async function waitReady() {
  for (let i = 0; i < 30; i++) {
    try { if ((await fetch('/health')).ok) return } catch {}
    await new Promise((r) => setTimeout(r, 500))
  }
  throw new Error('后端 15 秒内未就绪')
}
```

### 应用本身是别的应用的依赖时

一个快应用的后端同时是别的应用/会话的 MCP 服务或数据源（如既是应用又是 MCP server）时：

- **归属唯一**：它由自己的 `backend` 声明负责启动，用户点它的卡片即可
- **依赖方不要代起别人的端口**：判断服务在不在，**查 `GET /api/open/mcp` 清单**（MCP 型依赖）或探它的 `/health`，不在就提示用户「先启动 <应用名>」
- 依赖就绪同样走上面的轮询范式

## 重启与边界

- 同名应用的后端已在跑时，再点启动只开窗聚焦，不会重复起。要重启：先在终端里 Ctrl+C（或关掉那个终端），再点一次。
- 换代（改设置触发 core 重启）会**连带回收正在跑的后端**（终端随代际关闭），重启后重新点启动。
